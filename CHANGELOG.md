## [2.1.0] - 2026-10-27

### Added

- String checks and transforms from zod's string API: `@length`, `@nonempty`, `@startswith`, `@endswith`, `@includes`, `@uppercase`, `@lowercase`, and the transforms `@trim`, `@tolowercase`, `@touppercase` and `@normalize [form]`. Transforms run before every check, so `@trim` works with `@type email` and `@tolowercase` with enums. Tag names are now case-insensitive (#43).
- `@type uuid(v1)` to `uuid(v8)` to require a UUID version, and `@type guid` for UUID-shaped IDs without a valid version or variant (#18, thanks @montionugera).
- `@type httpurl` (http/https URLs only, via `z.httpUrl()`) and `@type hostname` (#19, thanks @montionugera).
- `@type email(<preset>)` with zod's `html5`, `rfc5322`, `unicode` and `browser` email patterns; `@default` is checked with the same preset (#20, thanks @montionugera).
- `@type time`, `time(precision=<n>)` and `duration`. Untagged ISO 8601 durations (`PT30S`, `P1D`) are now inferred as `z.iso.duration()` (#21, thanks @montionugera).
- `@type datetime(offset, local, precision=<n>)` for timestamps with an offset, without a timezone, or with a fixed number of fractional digits. Untagged datetimes with an offset (`2026-01-31T10:00:00+01:00`) are now inferred as `z.iso.datetime({ offset: true })` (#22, thanks @montionugera).
- `@type cidrv4`, `cidrv6`, `mac` and `mac(<delimiter>)` network formats. Untagged CIDR blocks (`10.0.0.0/8`, `2001:db8::/32`) and MAC addresses (`00:1A:2B:3C:4D:5E`) are now inferred (#23, thanks @montionugera).
- `@type base64`, `base64url` and `hex` encoding formats, with `@default`, length bounds (`@min` / `@max`) and `@pattern` support (#24, thanks @montionugera).
- `@type jwt`, `jwt(<alg>)` and `hash(<alg>[, <enc>])` (algorithms `md5`, `sha1`, `sha256`, `sha384`, `sha512`; encodings `hex`, `base64`, `base64url`), with `@default`, length bounds (`@min` / `@max`) and `@pattern` support (#25, thanks @montionugera).
- `@type nanoid`, `cuid`, `cuid2`, `ulid`, `ksuid` and `xid` ID formats, with `@default`, length bounds (`@min` / `@max`) and `@pattern` support (#26, thanks @montionugera).
- `@type e164`, `emoji`, `currencycode`, `iban` and `creditcard` string formats, with `@default`, length bounds (`@min` / `@max`) and `@pattern` support (#27, thanks @montionugera).

### Changed

- A failing `@min 1` / `@nonempty` on a string now reports `must not be empty` instead of `must be at least 1 characters`.

### Removed

- `@minlength` / `@maxlength`: use `@min` / `@max`, which already bound the length of strings. Generation fails with a hint if the old tags are still used.

## [2.0.0] - 2026-10-13

### Breaking

- Generated files import helpers from `type-envgen` at runtime, so install it as a regular dependency (`npm install type-envgen`, not `--save-dev`). The CLI adds it to `dependencies` for you.
- `@min` / `@max` on strings must be non-negative integers (a length).

### Added

- `type-envgen init` also adds `env:check` and `env:watch` scripts next to `env:generate`.
- `-w, --watch` flag to watch the input `.env` file and regenerate the output on changes. Your own code in the output file is kept (#5, thanks @montionugera).
- `--check` flag for CI and pre-commit hooks: exits `1` if the output file is missing or out of date with the `.env`, without writing files or installing anything. Your own code in the file and CRLF/LF differences don't count as changes (#4, thanks @montionugera).
- `@minlength <n>` / `@maxlength <n>` tags: explicit length bounds on string-like values (`string`, `url`, `email`, `uuid`, `date`, `datetime`, `ipv4`, `ipv6`). `@min` / `@max` stay as length aliases on strings (#10, thanks @montionugera).
- `@pattern <regex>` tag: validates strings, URLs, emails and UUIDs against a regular expression (`.regex(...)`). The `.env` value and any `@default` must match at generation time (#3, thanks @montionugera).
- Re-running on an existing output file updates it in place: only the `type-envgen` import, `envSchema` and the `env` line are regenerated, and your own code in the file is kept. Files generated by 1.2 are upgraded automatically.

### Changed

- Generated files import the `json` helper from `type-envgen` instead of inlining it. `type-envgen` is now a runtime dependency (install it without `--save-dev`); the CLI adds it to `dependencies` automatically, like zod.
- Missing or invalid variables now fail with a concise `[type-envgen]` error listing every problem, instead of a raw ZodError. Values are never printed.
- `@min` / `@max` on strings also work on `date`, `datetime`, `ipv4` and `ipv6`.

## [1.2.0] - 2026-10-08

### Added

- `--target node|vite|nextjs|astro|sveltekit|nuxt` to generate env modules for client-side frameworks (default `node`, output unchanged) (#12).
- `type-envgen init` interactive setup: explains each target and adds an `env:generate` script to `package.json`.
- Warning when a key lacks the client prefix of the chosen target (it would be `undefined` in the browser).

### Changed

- README rewritten, and package keywords updated.

## [1.1.0] - 2026-10-08

### Added

- Support and automatic inference for date/datetime and IP formats: ISO dates (`z.iso.date()`), ISO datetimes (`z.iso.datetime()`), IPv4 addresses (`z.ipv4()`), and IPv6 addresses (`z.ipv6()`) (#2).
- Supported `@type` annotations: `date`, `datetime`, `ipv4`, and `ipv6`.
- `# @default <value>` tag that emits `.default(...)`. The value is validated against the variable's type (including `@min`/`@max`) at generation time, and combining it with `@optional` is an error (#1).

## [1.0.1] - 2026-10-07

### Fixed

- `bin` path in `package.json` normalized (npm was auto-correcting it at publish time).

### Security

- Releases are now published through npm Trusted Publishing (OIDC) with provenance; no long-lived npm token is used.
- Dev dependency `esbuild` forced to `^0.28.2` to resolve GHSA-g7r4-m6w7-qqqr (dev server only, never shipped in the package).

## [1.0.0] - 2026-10-07

First public release.

### Added

- `type-envgen` CLI: reads a `.env` file and writes a typed, zod-validated `env.ts`
  (`type-envgen [input] [-o output]`, plus `--help` and `--version`).
- Type inference from values: booleans, integers, floats, URLs, UUIDs, emails, typed JSON,
  and a `NODE_ENV` enum, with `string` as the fallback.
- `# @type` annotations to override inference: `string`, `number`, `int`, `boolean`, `url`,
  `email`, `uuid`, `json` and `enum(a, b, c)`.
- `# @min` / `# @max` tags: bounds on numbers, length limits on strings.
- `# @optional` tag for variables that may be missing.
- Clear errors for unknown tags or types, invalid bounds and unsupported combinations.
- Adds `zod@^4` to your project automatically if it's missing, using npm, pnpm, yarn or bun
  (`--skip-install` to opt out).
